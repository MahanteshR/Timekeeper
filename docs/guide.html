A guide to installing and trying the free 0.7.1 Android beta.

Before installing: Android 12+ is required. Testing has focused on the Samsung Galaxy S25 Ultra. This is a debug-signed beta with independent security/release review and wider device testing still pending. Keep another way to access essential apps and try a nonessential app first.

1. Download and install

Download the APK on your Android phone and open it from the browser’s Downloads list or your Files app. If Android asks, temporarily allow installation from that specific browser or file app. Review the installer and install Timekeeper.

Download Timekeeper 0.7.1 ↓

After installation, you can turn that source’s installation permission off again. If Android or Play Protect shows a security warning, review it; do not disable security protections just to continue this beta.

2. Complete setup in Timekeeper

Open Timekeeper → Settings → Setup and permissions. Follow the app’s links to Android Settings.

  • Accessibility: enable Timekeeper’s service so it can identify the active app and show its blocker. On Samsung, look under Accessibility → Installed apps.
  • Usage access: enable it to provide usage history and support usage reconciliation.
  • Notifications: optional, for the remaining-time notification.

For sideloaded apps, Android may restrict enabling Accessibility. If you see “Restricted setting,” review the APK’s source and Android’s warning first. Android may offer App info → More options → Allow restricted settings. Choose this only after deciding to trust this beta. Menu names vary by device.

Some banking/security apps may refuse to run while Accessibility services are enabled. This beta does not offer a compatibility fix for those apps. No Shizuku, wireless debugging or root setup is needed for 0.7.1.

3. Add an app timer

Open App limits → Add, select an app, and set its daily allowance, session/interval length, cooldown and repeat days. Save the timer. Try a short allowance first and verify the blocking screen appears on your device.

For example: a 30-minute daily allowance, 10-minute sessions and a 3-hour cooldown. After each session is used, the app stays blocked during its cooldown. An active cooldown may continue past the daily reset. Unselected repeat days are unrestricted.

4. Save your setup

Open Settings → Back up and restore → Choose backup folder. Pick a private folder and wait for “Backup saved.” Timer configuration can then be restored together after reinstalling or changing devices.

Backups are not encrypted by Timekeeper and identify your selected apps. Usage history, live cooldowns and Android permission grants are not included.

What this beta can and cannot enforce

Timekeeper 0.7.1 uses an Accessibility-based blocking screen. A restricted app may appear briefly when launched. Its background audio or services may continue because this release does not suspend or force-stop other apps.

Strict mode locks changes to rules inside Timekeeper until the reset. Users retain Android’s controls over Accessibility permissions, app storage and uninstalling. It is not tamper-proof device management.

Check protection again after a reboot or any permission change. Background restrictions and manufacturer behavior can affect reliability.

Updating or returning from another beta

Save a timer backup before changing builds. Updates require a compatible signing certificate. Android may reject installing 0.7.1 over a newer beta such as 0.8.0. Uninstalling first removes local usage and runtime state; your saved configuration can be restored afterward. Do not uninstall while a restriction from an experimental Shizuku build is still pending—recover that restriction in that build first.

If you need to stop protection

Open Android Settings → Accessibility → Installed apps (or Downloaded apps) → Timekeeper and switch the service off. You can also revoke Usage access separately. Disabling the service stops Timekeeper’s Accessibility-based blocking.
